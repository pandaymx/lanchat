# lanchat 产品愿景与边界（Agent 必读）

> 每次动手前先读一遍。与 AGENTS.md 冲突时，以本文件的产品边界为准。
> 本文件是「为什么做这个项目」的权威来源，防止 agent 按自己的想象加功能。

## 一句话定位

**局域网即时通讯，Go 优先，面向程序员用户，覆盖 TUI / Web / 桌面 / 移动四端。**

## 核心卖点（项目存在的理由）

**多端同时在线、互不踢下线** —— 一个 User 可有多台 Device 同时在线，消息投递到该 User 的**所有**在线设备；每设备持有独立的读游标（`read_cursors(device_id, conv_id, last_seq)`）。

这是主流聊天软件的空白点（微信 / QQ 等普遍多端互踢或需扫码确认），是差异化所在。**任何功能都不得破坏或绕开多端模型（ADR-008）**。

## 边界（不做清单）

| 不做 | 原因 |
|---|---|
| 云账号注册 / 中心化服务器 / 互联网路由 | 定位是局域网内自持服务，无需公网账号体系 |
| 消息云端存储 | 数据留在局域网内，Hub 自持 SQLite |
| 音视频通话 / 端到端加密 / 机器人平台 | 未拍板前一律不引入，避免范围蔓延 |

## 决策准则

任何新功能先问两句：

1. **局域网场景下成立吗？**（不依赖公网、云、中心化注册）
2. **多端场景下成立吗？**（同一 User 双设备同时在线时依然正确）

任一不成立 → 先讨论再动手，不要直接实现。
