# ADR-002: pkg/core 接口与 transport 实现解耦

- 状态：✅ 已采纳
- 日期：2026-09-05（M1）
- 关联：AGENTS.md §3 架构铁律；ADR-008 / ADR-012

## 背景

项目面向 TUI / Web / 桌面 / 移动四端，需要一份跨端共享的业务内核。直接在各端实现里 import WebSocket 或平台 API 会导致：

- 换传输架构（一期 ws → 二期 gRPC/QUIC）要改所有端
- gomobile bind 要求 `pkg/` 可被外部 import，`internal/` 不可达
- 业务逻辑与传输实现强耦合，无法单独测试

## 决策

- `pkg/core` 只定义接口：`Transport` / `Conn` / `EventBus` / `Subscription` / `Store`（M1 五接口）+ 高层 `Client` API
- 业务层只认接口，不认 WebSocket、不认 SQLite、不认 IP 地址
- `pkg/hubstate.Router` 一份逻辑同时服务 fake Hub 与真 Hub（transport 可替换点）

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 每端各写一套业务逻辑 | 四份重复维护，多端一致性无法保证 |
| 业务层直接 import WebSocket | 换传输架构 = 全端返工，破坏可测试性 |

## 落地位置

- `pkg/core/`（client.go / transport.go / store.go / event.go / model / protocol）
- `pkg/hubstate/router.go`（fake 与 ws 共用的调度逻辑）
- `pkg/transport/{fake,ws}/`（两种 Transport 实现）

## 验证

- M1 fake Hub 与 M2 真 Hub 共用 `hubstate.Router`，业务逻辑零分支
- M2 换成 ws transport 时 `pkg/core` 零行修改
- `pkg/client` 4 个验收测试在 fake/ws 下同源通过
