# ADR-003: 前端选型 templ + HTMX

- 状态：✅ 已采纳
- 日期：2026-09-05（M4 筹备期拍板）
- 关联：AGENTS.md §2 技术栈硬性约束；ADR-011 / ADR-012

## 背景

M4 Web 端需要一个浏览器端方案。项目技术栈以 Go 为主，目标是零前端构建链、离线可跑、反代零配置。

## 决策

- 前端用 **Go 全栈 templ + HTMX**：templ 生成 Go 渲染函数，HTMX 负责轻量交互
- htmx 与 SSE 扩展 **vendored 进 embed.FS**，零 CDN 依赖、离线可跑
- **不引入** React / Vue / 任何 JS 框架，**不引入**前端构建工具（webpack/vite 等）

## 备选方案

| 方案 | 否决理由 |
|---|---|
| React / Vue + 构建工具链 | 引入 Node 构建链 + 双语言维护，违背 Go 全栈定位 |
| 纯原生 JS | 交互状态管理成本高，templ + htmx 已覆盖需求 |

## 落地位置

- `internal/webui/`（templ 模板 + static/htmx.min.js + sse.js + style.css，`assets.go` embed）
- `Makefile` / CI：`templ generate` 先行（`*_templ.go` 不入库）

## 验证

- M4.2 起三路由（/ /events /api/messages）用 templ + htmx-sse 实际渲染
- vendored htmx 内嵌后真机离线可跑
