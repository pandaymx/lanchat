# ADR-008: User/Device 二层身份与 per-device 读游标

- 状态：✅ 已采纳
- 日期：2026-09-05（M1）
- 关联：AGENTS.md §7；`.agents/rules/vision.md`（核心卖点）；`.agents/rules/multi-device.md`

## 背景

主流聊天软件多端互踢或需扫码确认。本项目差异化卖点是**多端同时在线不互踢**。若用 user 级游标（`conversations.last_seq`），第二台设备会漏消息或重复拉全量。

## 决策

- 身份分两层：`User`（人）与 `Device`（设备），一个 User 可有多个 Device 同时在线
- 消息投递到该 User 的**所有**在线 Device（不是互踢）
- 同步游标是 **per-device** 的：`read_cursors(device_id, conv_id, last_seq)`
- 一期一个 Device 即一个身份；结构支持一对多，UI 暂不暴露

## 备选方案

| 方案 | 否决理由 |
|---|---|
| user 级游标 `conversations.last_seq` | 第二台设备漏消息或重复拉全量 |
| 多端互踢 | 违背核心卖点 |

## 落地位置

- `pkg/hubstate/registry.go`：User → Device → Conn 三层索引
- `pkg/hubstate/router.go`：`FKRead` 写 per-device 会话游标；`FKDeliver` 按 user 扇出到所有在线设备
- `cmd/web/main.go`：web 端 device 标识 `web-<8 位随机十六进制>`（每进程不同，符合 ADR-008）

## 验证

- `TestMultiDeviceCursor`（M1 验收第 4 条）
- `TestRegistryMultiDeviceFanout`（一个 User 的多台设备都能收到）
- `TestRouterReadCursorPerDevice`（游标 per-device 独立推进）
- 真机：同一 user 两个 TUI 窗口同时在线互发不互踢
