# ADR-009: Client 内部 pumpCtx 隔离 readPump 生命周期

- 状态：✅ 已采纳
- 日期：2026-09-05（M3 排障）
- 关联：AGENTS.md §12 不确定时；`.agents/workflow/milestone-flow.md` ctx 铁律

## 背景

真机 demo「发消息是空的」：`cmd/tui` 的 `dialSession` 用 `context.WithTimeout(Background(), dialTimeout)` 创建 dialCtx 后一路传给 `tui.Dial → cli.Connect → readPump`。函数返回时 `defer dialCancel()` 触发，readPump 第一行 `Recv(ctx)` 立即拿到 canceled 退出——**消息发出去了（hub 广播了），但客户端 readPump 死了读不回来**。

## 决策

- Client 内部自起 `pumpCtx = context.WithCancel(Background())`，**只**给 readPump 用
- `Connect` 传入的 ctx 只管 dial / handshake 阶段
- `Close()` 顺序：`pumpCancel()` → forceFlushPending → `conn.Close()`，让 readPump 走「ctx canceled」正常路径退出
- 顶层构造点无父 ctx，`//nolint:contextcheck` 标注（比改 API 破坏调用方代价低）

## 备选方案

| 方案 | 否决理由（用户拍板） |
|---|---|
| A：Dial 拆分 ctx（只改 session.go） | 只修表象，Client API 语义仍脆弱 |
| **B：Client 内部 pumpCtx**（已选） | 根因修复，readPump 生命周期归 Client 自己管 |

## 落地位置

- `pkg/client/client.go`：`pumpCtx` / `pumpCancel` 字段 + Connect/Close 改造（commit 0f0225f）

## 验证

- `TestClientInternalPumpCtx_CloseCancelsReadPump`（Close 后 2s 内 readPump 退出 + 二次 Close 幂等）
- `TestExternalCtxCancelDoesNotKillReadPump`（dialCtx cancel 后仍能收 FKDeliver——bug 最小复现）
- 真机日志：修复后出现 `readPump started` + `readPump exited after close`（而非 `recv failed`）
