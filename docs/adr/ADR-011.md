# ADR-011: Web 端用 SSE + POST /api/messages，不用 WebSocket

- 状态：✅ 已采纳
- 日期：2026-09-05（M4.1 拍板）
- 关联：ADR-012；AGENTS.md §2 传输约束

## 背景

M4 Web 端需要浏览器 ↔ web server 通信方案。备选：SSE / WebSocket / 长轮询。

## 决策

- **SSE**（单向 server→client 推）：`GET /events`，浏览器 `EventSource` 原生支持，断线自动重连
- **POST /api/messages**（client→server 写）：消息上行走普通 HTTP POST
- 不用 WebSocket——浏览器 EventSource 零配置，nginx / Caddy 反代穿透只需关 `proxy_buffering`

## 备选方案

| 方案 | 否决理由 |
|---|---|
| WebSocket | 反代需额外配置；浏览器 API 复杂；一期只需单向推流 + 上行 POST |
| 长轮询 | 延迟与连接开销高，SSE 已覆盖需求 |

## 落地位置

- `internal/webui/handler.go`：`GET /events`（SSE 流，`event: message` + `id: <seq>` + `data: <html>` 帧）+ `POST /api/messages`
- M8 TLS 阶段再处理反代 buffering 细节

## 验证

- M4.3 E2E：fake hub + 双 web 实例，POST hello → 双方 SSE 3s 内都收到 message 帧
- 真机冒烟：`GET /events` 返回 `text/event-stream` 首帧 `: lanchat sse ready`
