# ADR-014: 去中心化 mesh —— 每节点嵌入式 hub + wire v2

- 状态：✅ 已采纳
- 日期：2026-09-13（v2.2 迭代期拍板）
- 关联：AGENTS.md §3 架构铁律；ADR-008（per-device 游标）；ADR-012（多端协议）

## 背景

现状是星型模型：`client ──► hub`，hub 是唯一权威存储 / 转发 / 文件宿主。
痛点：

- 单点：hub 不在线，所有客户端不能收发；历史与文件单副本，hub 丢失即全丢
- 部署负担：四端客户端要先有一个可用的 hub 才能聊天
- 用户决策：要**真正的去中心化**——没有中心 hub，每个节点都是本地 hub，
  靠节点间同步构成网络。局域网信任模型 = 能连上就是成员，不需要安全性
  （用户明确拍板）。

## 决策

1. **wire v2 全新协议，不兼容旧 hub / 旧客户端**（用户拍板）。
   旧数据不迁移进 mesh（另立迁移方案或只读归档）。
2. **每节点嵌入式 hub**：客户端库内启动 hub（复用现有 router / store /
   transport），数据落 `pkg/appdir`。独立 hub 二进制退役，仅保留为调试工具。
3. **监听默认全局（`0.0.0.0`）**：局域网共享优先；设置项可切回 `127.0.0.1`
   （隐私模式）。不做鉴权：信任 = 局域网可达。
4. **全节点同步**：消息与文件附件都同步到所有在线节点（全量复制模型）；
   离线节点上线后按游标增量补齐。不做点对点按需拉取。
5. **消息序**：不再有全局 hub seq。消息 ID = `(nodeID, seq)`，seq 每节点
   局部单调递增；显示顺序按 `(nodeID, seq)` 字典序 + 本地合并视图。
6. **同步机制**：按「源节点」维度的游标增量拉取，幂等去重（同一消息
   同步多次不重复落库）；UDP 局域网发现（广播 / mDNS）找到对等节点。
7. **数据完整性（非安全）必须做**：同步幂等、乱序防护、离线期间两侧
   各写消息的合并不丢帧。
8. **文件**：作为消息附件随全节点同步落各节点存储（替代点对点拉取）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| wire v1 兼容桥接层 | 用户拍板不兼容；双协议长期维护，去中心化不彻底 |
| 保留中心 hub + 嵌入式降级为可选项 | 用户要求真正的去中心化，中心概念取消 |
| 文件点对点按需拉取 | 用户拍板全节点同步；全量复制实现更简单，复用现有 blob 存储 |
| 节点间加密 / 鉴权 | 用户明确局域网不需要安全性；信任模型 = 局域网成员 |

> **M-b 广播闭环**（2026-09-13）：mesh 同步落库后经
> `hubstate.Router.DeliverSynced` 实时推送 FKDeliver 给本地已连接客户端；
> `AppendSyncedMessage` 返回是否新插入，重复同步不重复推送。

> **M-c 多节点历史视图**（2026-09-13，LocalSeq）：新增 `local_seq` 本地
> 单调视图序，作为本地视图的权威顺序——排序、补发（FKHistoryReq）、
> 分页游标全部切到 LocalSeq；同步消息由接收节点强制重新分配 LocalSeq，
> 落库后可进补发缓冲（M-b 的"同步消息不进 History"限制解除）；广播闭环
> 用 `GetSyncedMessage` 取回落库权威消息，源节点 LocalSeq 不泄漏。

> **M-c 群成员一致性**（2026-09-14）：新增会话事件流（`conv_events` 表，
> per-source 游标 + 全量复制，与消息同步同构）——建群/邀请/退群在产生
> 节点落事件、`mesh_loop` 拉取落表后 `ApplyConvEvent` 幂等应用（成员
> union 合并、left 移除），四端运行时注册表/权限模型收敛一致。

> **M-c presence 广播**（2026-09-14）：presence 是易失状态，不走持久化
> 事件流——每次 mesh 同步顺带交换双方在线用户快照（覆盖式）+ 本地
> 上下线时经 `/api/v1/mesh/presence` 即时推送邻居（router 的
> `MeshPresenceSink` 回调，TOFU + Envelope 加密）；远端应用只广播不
> 触发 sink 防回声环。

> **M-c 文件全节点同步**（2026-09-14）：文件是大件，不做全量复制——
> 下载端点本地未命中时经 mesh `fetch-through` 从邻居按 FileID 拉取
> （blob 流式转发、meta 落本地、幂等落盘），此后本地直接命中。

> **P2 移动端**（2026-09-14）：通知震动开关（设置页「消息通知」新增
> `notify_vibrate` 偏好，发通知前读偏好决定 enableVibration）；表情面板
> 搜索（`_emojiKeywords` 与 `_emojiList` 一一对应的 60 条中/英/拼音关键词，
> TextField 实时过滤网格）；大厅用户信息卡（MessageBubble 加 `onUserTap`，
> 他人头像/用户名可点弹底部卡片：同款色板头像、用户 ID、在线状态、「提到
> TA」一键插入 `@名字 ` 并聚焦；自己/群聊不触发）。长按引用/转发此前已有。

> **P2 桌面端会话列表数据层**（2026-09-14，`b81ab13`）：协议
> ConversationSnapshot 不变，Session 内联维护数据层——事件泵累积
> `touchConv`（预览/时间/未读，非当前会话未读+1）、`setConv` 切换清零、
> 首屏 `backfillConv` 拉最近一条回填；模板渲最后消息预览（42 字截断）、
> 时间列（今天 HH:mm/昨天/M月d日）与未读角标；群无预览显成员数、大厅显
> 空态文案（新增 `web.conv.empty` i18n key）。

> **删除 hub 依赖·第一步**（2026-09-15，`ff3b0cb`）：桌面端 `-embedded`
> 默认 true——HubURL 为空时进程内起 `pkg/hubserver`（127.0.0.1 随机端口 +
> mesh + mDNS），免去「先另跑 hub 进程」；`cmd/hub` 降级为显式独立部署。
> 顺带修了 hubserver 端口 0 场景 `Addr()` 只返回 `:0` 的缺口（预绑定取真实
> 端口）。TOFU 不受影响：mesh_identity.bin 持久化，127.0.0.1 公钥跨重启稳定。

> **删除 hub 依赖·第二/三步**（2026-09-15，`f8d8a95` / `30e02f5`）：抽共享
> 入口 `hubserver.StartEmbedded`（本进程专用：回环随机端口 + Mesh 固定
> true，覆盖项走 cfg，关停靠 ctx cancel），desktop 重构复用、tui 与 web
> 同款接入（默认 `-embedded` true）。至此三端装完即用，独立 hub 进程
> 不再是前置步骤；真实冒烟：无外部 hub 进程时 web 端首页 200。

> **删除 hub 依赖·第四步**（2026-09-16，`33e28d9`）：移动端内嵌 Go hub——
> 安卓 App 启动时进程内起 hub（127.0.0.1 随机端口 + mesh + mDNS），
> Dart 直连本地 ws。技术选型：NDK clang 交叉编译 c-shared
> `liblanchub.so`（arm64-v8a，入 jniLibs）+ dart:ffi 直调，绕开
> gomobile/javac 工具链依赖；连接页默认「本机模式」，so 缺失或启动
> 失败回退手动地址。构建：`mobile/cmd/androidhub` 内注释给出 CC 命令。

> **节点身份 / 配对 Token 握手**（2026-09-16，`95a5eee`）：把「按来源 IP 的
> 纯 TOFU」升级为「X25519 公钥指纹为节点身份 + 设备名记录 + 配对 Token
> gated TOFU」。`pkg/mesh/handshake.go`：`NewToken`（32B 随机 → base32 52 字符
> 无填充）/`HashToken`（服务端只存 SHA-256）/`PeerID`（sha256(pub)[:16] hex
> 32 字符，换 IP 不丢信任、无法冒充）/`authorizePeer`（已知放行 → 未配 Token
> 旧 TOFU → 有 Token 必须校验，错/空白拒绝且不记录）。`KnownKeys` 磁盘格式
> v2 `{"keys":..,"names":..}`，v1 兼容加载；`cmd/hub` 新 flag
> `-join-token`/`-print-join-token`/`-device`/`-mesh-dir`。冒烟：无 Token 新
> 节点被 403 `peer not authorized` 拒绝，带 Token 新节点成功同步且服务端
> 落盘 32 位 hex 指纹 + 设备名。已知边界：客户端侧 known-keys 仍以
> baseURL 为键（v1 遗留），仅服务端升级为指纹键；双向设备名展示待后续。

## 落地位置

- `pkg/hubserver/`（hub 启动逻辑从 `cmd/hub` 抽出，可库内调用）
- `pkg/protocol/`（wire v2 帧：同步 / 游标 / 发现）
- `pkg/core` / 各客户端连接层（目标地址 = 本机 embedded hub）
- 旧 `cmd/hub` 保留为调试/单机模式入口
